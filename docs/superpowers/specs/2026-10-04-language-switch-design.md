# 日本語 / English 切り替え 設計

日付: 2026-10-04  
状態: 設計（実装前）  
親仕様: [2026-09-18-stream-heartbeat-design.md](./2026-09-18-stream-heartbeat-design.md)

操作用ウィンドウの表示を日本語と英語で切り替えられるようにする。切り替えはボタン 1 つで、アプリを再起動せずにその場で変わる。

## 目的

- 英語圏の配信者も、操作用ウィンドウの文字を読んで使えるようにする。
- 日本語の利用者には何も変わらない（既存の見た目・動き・保存データはそのまま）。

## 非目標

- 日本語・英語以外の言語、OS の言語に合わせた自動切り替えの再実行（初回起動の既定だけ OS に合わせる）。
- 配信用ウィンドウの題名の翻訳（下の「変えないもの」）。
- 利用者が自分で入れた文字（同期文字の文言、プロファイル名）の翻訳。
- README の全文英訳（末尾の英語概要は別途ある）。

## 画面

| 場所 | 内容 |
| ---- | ---- |
| 「心拍の補正」の見出しの行 | 見出しボタンの右に、小さな言語ボタンを 1 つ置く。日本語表示のときは `English`、英語表示のときは `日本語` と出る（押すと、その言語になる） |
| 押したとき | 操作用ウィンドウの文字がその場で入れ替わる。言語は保存され、次の起動でも引き継ぐ |

言語ボタンの文字は翻訳しない（`English` / `日本語` は、押した先の言語の名前）。

## 変えないもの

- **配信用ウィンドウの題名** `StreamHeartbeat(ぬ) - 配信出力` と操作用の題名 `StreamHeartbeat(ぬ)`。OBS は題名でウィンドウを探すので、言語で変えると取り込みが外れる。英語表示でも日本語のまま固定し、OBS の案内文にもこの題名をそのまま出す。
- プロファイルの保存形式。スタイル・色・背景などは「表示名」ではなく「保存する値」（`itemData`）で持っているので、言語を変えても壊れない。
- 配信用ウィンドウの描画（心臓・同期文字・BPM の数字）。

## 仕組み

### 1. `i18n.py`（新規）

- `language() -> "ja" | "en"` / `set_language(lang)`。
- `tr(text, **fmt) -> str`: 日本語の原文をキーにして、英語表示のときは英訳を返す。英訳が無ければ日本語のまま返す。`fmt` があれば、訳したあとで `str.format` する（`tr("「{name}」として保存しました", name=name)`）。f 文字列は使わず、`{}` つきの文にする。
- `translate_tree(root)`: ウィンドウ内の部品を走査して、文字を今の言語に付け替える。
- 初回の言語: 保存済みの `app_state` の `"language"` があればそれ。無ければ OS の言語が日本語なら `ja`、それ以外は `en`（保存はボタンを押したときだけなので、押すまでは OS に追従する）。起動中の小窓（splash）より前に決める。読むのは `paths` と JSON だけで軽い。

英訳の表は `i18n_en.py`（新規）に分ける。`{日本語の原文: 英語}` の辞書で、800 行を超えそうなら画面ごとに分割する。

### 2. 走査して付け替える（`translate_tree`）

操作用ウィンドウの部品は、いまのコードのとおり日本語で作る。その後に `translate_tree(self)` が次を英語に付け替える。

| 部品 | 付け替える文字 |
| ---- | -------------- |
| `QLabel` / `QAbstractButton`（チェック・ボタン・折りたたみ見出し） | `text()` |
| `QGroupBox` | `title()` |
| すべての部品 | `toolTip()` |
| `QLineEdit` | `placeholderText()` |
| `QComboBox`（`MarkedComboBox`） | 各項目の表示名（`itemData` の値は触らない） |

元の日本語は、部品ごとに動的プロパティ（`i18n_text` など）へ最初に 1 回だけ覚える。日本語に戻すときはそれを使う。

**走査が触ってよい部品の条件（安全装置）**: いまの文字が「覚えた日本語」か「その英訳」に一致するときだけ付け替える。実行中に別の文字が入った部品（状態の帯、通知、BPM の数字など）は、一致しないので触らない。そういう文字は次の「呼び出し側」で `tr()` を使う。

### 3. 呼び出し側で `tr()` を使う文字

実行中に作られる文字は、`setText` の場所で `tr()` を使う。

- 状態の帯と通知（`PREVIEW_*` / `LIVE_STATUS`、`_flash(...)`、保存失敗、マイクを開けない、音が届かない、補正中の表示）
- 確認ダイアログと入力ダイアログ（`QMessageBox.question`、`QInputDialog.getText`）
- 別の文字を埋め込む文（`cal_hint` は「補正開始」「補正を保存」のボタン名を含む。`obs_hint` は背景ごとに変わる）
- 演出の説明（`EFFECT_HINTS`）と、スタイルによって作り直される演出の一覧（`effects.py`）。スタイル名・色・背景の名前は、作ったあと変わらないコンボなので走査で付け替える
- 保存した値が選択肢に無いときに足す項目（`保存値 {value}`）
- VTube Studio 連携の状態表示（`vts_panel.py` / `vts.py` から画面に出る文字）
- 折りたたみ見出し（`fold_toggle` は ▶/▼ と題名をその都度組み立てるので、題名の日本語を覚えておき、組み立てるときに `tr()` する）
- 起動中の小窓（splash）の文言

`config.py` の文字定数（`LIVE_STATUS` など）は日本語のまま残し、使う側で `tr()` する。`t.text() == 定数` のように文字で判定している所は、文字ではなく状態の値で判定し直す（`operator_window.py` の `startswith("時計と数字")` など）。

### 4. 言語を切り替えたときの流れ

`OperatorWindow._set_language(lang)`:

1. `i18n.set_language(lang)` と `save_app_state(language=lang)`。
2. `translate_tree(self)`。
3. 作り直しが要る部分を呼び直す: `_refresh_style_controls`（演出の一覧と説明、OBS の案内）、`_sync_cal_ui`、`self._vts` の更新。状態の帯は 16 ms ごとの更新で、すぐ入れ替わる。
4. 言語ボタンの文字を入れ替える。

ウィンドウは作り直さない。マイク・タイマー・プロファイル・配信用ウィンドウには触らない。

## 英訳の方針

- 言葉は一覧で統一する（例: 心拍の補正 = Heartbeat calibration、スタイル = Style、演出 = Effect、プロファイル = Profile、同期文字 = Beat text、配信用の窓 = output window、操作用 = control window）。
- 英語表示でも、OBS の用語（ウィンドウキャプチャ = Window Capture、クロマキー = Chroma Key、カラーキー = Color Key）と README の英語概要の言い方に合わせる。
- 英語は日本語より長い。折り返しと最小幅で崩れないことを、両方の言語で目で確かめる。

## テスト

- `tests/conftest.py` で、テストの間は言語を `ja` に固定する（既存のテストは日本語の文字を前提にしている）。
- `tests/test_i18n.py`（新規）:
  - `tr()` が英語・日本語・英訳なし（日本語に戻る）・`{}` つきで正しく動く。
  - **英訳の抜け**: ソース中の `tr("…")` の最初の引数の文字（定数経由は定数の値）がすべて表にある。
  - **画面の漏れ**: 英語にした `OperatorWindow` の全部品を走査して、ひらがな・カタカナ・漢字が残っていない（許すのは題名と `日本語` ボタンの名前、利用者の入力欄の中身）。VTube Studio 連携の欄は、状態を変えて（つながっていない・確認待ち・許可されなかった・心臓あり）それぞれ確かめる。
  - **切り替えの往復**: ja → en → ja で、全部の文字が元に戻る。プロファイルの値（選んだスタイル・色・背景）が変わらない。
  - 保存と起動時の既定: 保存した言語が引き継がれる。保存が無いとき、OS が日本語なら `ja`、それ以外は `en`。
- 目での確認: 操作用ウィンドウを両方の言語で撮って並べる（`visual-check-styles` のやり方）。

## 作業の分け方

1. `i18n.py`・`i18n_en.py` の骨組みと、保存・初回の言語・テストの土台。
2. 操作用ウィンドウ（`operator_window.py`、`operator_controls.py`、`fold.py`、`slider.py` 周り）と言語ボタン。
3. スタイル名・演出・色・背景（`style_catalog.py`、`effects.py`、色の一覧）。
4. VTube Studio 連携（`vts_panel.py`、`vts.py`）。
5. 起動中の小窓・状態の帯・エラーの知らせ（`splash.py`、`app.py`、`config.py`、`session.py`、`audio.py` など）。
6. 目での確認と、README の英語概要の 1 文（「画面は日本語だけ」）を直す。

## 決めたこと・リスク

- 英訳の表が日本語の原文をキーにするので、日本語の文を直したら表も直す。直し忘れは「英訳の抜け」のテストで落ちる（静的な部品の文字は「画面の漏れ」のテストで見つかる）。
- 実行中だけ出る文字の訳し忘れは、テストの状態を網羅できていないと残る。主な状態は上のテストで通す。
- 切り替えの前に出た通知（例: 「保存しました」）は、消えるまで元の言語で残る。数秒で消えるので許す。
