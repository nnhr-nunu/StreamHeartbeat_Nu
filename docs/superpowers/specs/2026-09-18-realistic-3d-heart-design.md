# リアル心臓 3D（OpenGL）設計

日付: 2026-09-18  
状態: 合意待ち（チャットで方針合意、このファイルの確認後に実装計画へ）  
親仕様: [2026-09-18-stream-heartbeat-design.md](./2026-09-18-stream-heartbeat-design.md)

配信の「リアル」スタイルを、同梱メッシュの立体心臓にする。医療機器ではない。診断しない。

## 目的

心音の時計に合わせて、内蔵の心臓が縮み・捩れ・太い血管が膨らみ、血液が押し出される感じを出す。見た目は今は 2 種で切り替え、あとから断面図などを同じ一覧に足せる。

## 非目標（この変更）

- Three.js / ブラウザ埋め込み / Chromium
- ユーザーが任意の 3D ファイルを読み込む
- 手術器具・開胸の周囲・縫合糸
- 断面図そのもの（枠だけ空ける）
- 配信用キャンバスへのデバッグ文字
- かわいい / 機械 / 心電図の 3D 化

## 画面

配信用の窓はこれまで通り OBS が取り込む。背景は固定緑 `#00FF00`。心臓の画素はこの緑を使わない。

| 場所 | 操作 |
| ---- | ---- |
| 配信用キャンバス | 左ドラッグで心臓を回す。心臓は画面中央のまま。左右ドラッグが横回転、上下ドラッグが縦回転。ホイールでは大きさを変えない（大きさは操作画面のスライダー） |
| 操作画面 | スタイルがリアルのときだけ「見た目」一覧と「角度を固定」を出す。固定オンのあいだは配信用のドラッグを無視する。固定は起動のたびにオフ。角度の数値自体はプロファイルに保存する |

初期の向きは解剖図寄り（尖が画面の左下、基部が右上）。手術映像は上下が逆なので、ドラッグでそちらにも寄せられる。縦回転は ±89° で止め、真横で裏返り続けない。横回転は一周できる。感度は 0.35° / ピクセル。

同期文字と BPM 数字は今と同じ重ね書き。配信用にファイル名・例外・内部値は出さない。

## 見た目の切り替え

形はメッシュ 1 体。質感だけ変える。キーはプロファイル `realistic_look`。

| キー | 操作画面の名前 | 質感 |
| ---- | -------------- | ---- |
| `surgical` | 手術寄り | 黄色い脂肪、冠動脈、湿った強い光沢。器具は出さない |
| `anatomy` | 教科書寄り | 脂肪を抑え、溝と血管が読みやすい。光沢は弱め |

追加は同じ表に行を足す。断面図は将来この表のキー（例: `section`）として足す。断面の切断面・内腔の塗りはこの変更では実装しない。

不明なキーは `surgical` に落とす。

## 拍動

時計は今の `CardiacCycle`（心音が正本）。全体を同じ倍率で潰さない。

| 部位 | 収縮（squeeze） | 送り出し（eject） | 充満（fill） |
| ---- | --------------- | ----------------- | ------------ |
| 左室 | 中へ強く縮む。尖が基部へ寄る | — | ゆるむ |
| 右室 | 左室の約 0.65 倍 | — | ゆるむ |
| 心房 | 室が縮むとき少し膨らむ | — | 室がゆるむと戻る |
| 尖 | 基部方向へ寄る。長軸まわりに捩れる | — | 戻る |
| 基部・血管の根元 | ほぼ固定 | — | — |
| 太い血管（大動脈など） | — | 径が最大 +12% まで膨らむ | 戻る |
| 表面 | ごく弱い揺れ（拍そのものではない） | 濡れのハイライトが少し強くなる | — |

捩れは尖で最大 18°、基部で 0。エンタメ用の目安であり、実測のねじれ角を再現しない。

血液の飛びは今の 2D（`ejection_blobs`）を 3D の上に重ねる。血管の膨らみと赤い飛びの両方で「送り出している」感じを出す。

## 描画の箱

描画エンジンは一つ、スタイル差し替え、は親仕様のまま。

- 配信用キャンバスを `QOpenGLWidget` にする。追加の 3D ライブラリは入れない（PySide6 の OpenGL）。
- リアルかつ GPU 初期化成功: 緑を塗り、メッシュを変形して描き、その上に QPainter で血液・文字・BPM。
- それ以外のスタイル: 今の 2D 描画。
- OpenGL を初期化できない、またはシェーダーが通らない: 今の 2D リアルに戻す。操作画面にだけ短い失敗表示。配信用には出さない。
- 教科書寄りでは脂肪の頂点も残し、色だけ筋色に寄せる。領域を消さない。
- 大きさ・透明度スライダーは 3D にも即反映。

## メッシュ

アプリに 1 体同梱する。外部の有料・ライセンス不明モデルは使わない。リポジトリ内の生成コードで OBJ と部位マップを書き出し、その成果物を `src/stream_heartbeat/assets/heart/` に置く。

| ファイル | 中身 |
| -------- | ---- |
| `anatomy.obj` | 位置と法線。三角形のみ |
| `anatomy.regions` | 頂点ごと 1 バイトの部位 ID（左室 0、右室 1、心房 2、血管 3、脂肪 4） |

頂点はおおよそ 4 千〜1 万。実行時に読み、CPU で毎フレーム全頂点を動かさない。変形は頂点シェーダー。部位 ID は頂点属性にする。

生成コードはテストできること（部位 ID の範囲、三角形が閉じている、頂点数が下限以上）。配布物は生成済みファイルを使う。起動のたびに生成しない。

## プロファイル

追加フィールド（既存 JSON に無いときは既定）:

| フィールド | 既定 | 意味 |
| ---------- | ---- | ---- |
| `realistic_look` | `"surgical"` | 上表のキー |
| `heart_yaw_deg` | `-18` | 横回転 |
| `heart_pitch_deg` | `12` | 縦回転（尖が左下に見える初期角） |

`angle_lock` は保存しない。

## 失敗と境界

- メッシュファイル欠損: 2D リアルへ。操作画面にだけ「3D 心臓を読めませんでした」。
- ドラッグ開始が「角度を固定」オン: 無視。
- スタイルをかわいい等へ変えても yaw/pitch は捨てない。リアルに戻したら同じ向き。
- 断面キーがまだ無いのにプロファイルへ書いた場合: `surgical` に落とす。

## テスト

GPU は pytest で要求しない。

- プロファイルの読み書き（新フィールド、未知キーの落下）
- 部位 ID と変形の数式（CPU で 1 頂点: 左室は右室より縮む、血管は eject で太る、基部はほぼ動かない）
- 縦回転のクランプ
- 見た目キーの登録表（2 件、後から行を足せる）
- 窓タイトル契約は既存のまま

## 回帰（人が見る場所）

- 配信用: 緑の上の心臓・血液・文字・BPM だけ。角度ドラッグの結果が見える。
- 操作画面: 見た目一覧、角度固定、3D 失敗時の文言。「医療機器ではない」は残す。
